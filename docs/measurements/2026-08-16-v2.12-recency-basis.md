## Qualitative — live `memoryctl rank --query` before/after

Three prompts, top-8 slugs from each binary. The "before" column was captured
by the main session from the installed v2.11.0 binary before any v6 code ran
(files `livecopy/rank-before-*.txt`, pasted here). The "after" column was
produced against a scratch v6 sidecar built with `CLAUDE_MEMORY_DIR` pointed
at a copy of the live WAL, so the live install's own sidecar and WAL were
never touched; `go run ./cmd/memoryctl sidecar rebuild` built that scratch
sidecar from the WAL copy plus the (read-only) live native files, then
`go run ./cmd/memoryctl rank --query … --k 8` ran against it. `rank` is
unscoped (`s.All()`), so rows from other projects appear; compare within the
same scope both times.

### Summary

Across the three prompts, no fact that strictly satisfies ref≥50 AND eff<0.3
left a top-8 in this snapshot — the closest is
`ui-gate-on-id-hides-namesonly-records.md` (prompt 1, ref=91, eff printed as
0.30, i.e. right at the boundary). The clearer signal in this data is the
opposite direction: facts with very high ref_count and low effectiveness
(`no-internal-docs-in-public-repo.md` ref=461/eff=0.08,
`design-system-migration-claude-ai-handoff.md` ref=462/eff=0.03) now enter
the top-8 specifically because they were cited useful *today*, and
`parallel-worktree-subagent-migration.md` (ref 620–621, eff 0.04–0.05 — the
CHANGELOG's illustrative example) held its position for the same reason —
not because it keeps re-injecting. The corpus captured for this run happens
to have a burst of same-day `trigger-useful` events, which flattens the
before/after contrast for facts that would otherwise have decayed; the A/B
replay above (97 sessions, no same-day bias) is the more reliable read on
the size of the effect.
